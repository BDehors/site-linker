## 0. 先更正我上午口头说错的两处

| 上午的说法 | 核实后的实际情况 |
|------------|------------------|
| "隐私政策 URL：Edge 强制（比 Chrome 严）" | 官方措辞是"**扩展访问、传输或收集任何个人信息时，你必须提供隐私政策 URL**"。我们不收集数据，严格说**非必填**；但建议填（PRIVACY.md 链接，零成本，还能减少审核员疑问） |
| "截图 ≥1 张" | 官方文档标注 **Optional（非必填）**，最多 6 张，每张 1280×800 或 640×480。仍然建议至少放 1 张 |

另外澄清一个容易混的点：**商店 logo 和包内 manifest 图标是两回事**。商店 logo 在表单里单独上传（见下）；包内 `icons/` 是本项目自选的 16/48/128，Edge 未强制规定其尺寸。

## 1. 注册（免费）

官方原话（2026-10-13 抓取）：

> "There is no registration fee for submitting extensions to the Microsoft Edge program."
> — [Register as a Microsoft Edge extension developer](https://learn.microsoft.com/microsoft-edge/extensions-chromium/publish/create-dev-account)

步骤：

1. 准备一个 Microsoft 账户（Outlook/Live/Hotmail），**或直接用 GitHub 账户登录 Partner Center**（系统会自动创建 MSA）——我们已有 GitHub，走这条最快。
2. 进 [Partner Center](https://partner.microsoft.com)，Account settings → Programs → Microsoft Edge 卡片 → Get started。
3. 填表：Account country/region（**注册后只读，想清楚再选**）、Account type 选 **Individual**（个人）、Publisher display name、联系人信息。
4. 等注册验证（官方提到可能延迟，不是秒过）。

## 2. 要交的东西

### 2.1 扩展包 zip

- 提交位置：`提交包/01-商店提交/站点链接助手-v1.9.0.zip`（manifest.json 在 zip 根目录，**不能套多层文件夹**）。
- manifest 为 **MV3**。Edge 88+ 完整支持 MV3；Chrome 商店现已只接受 MV3，所以同一个包发两家是唯一稳妥解。
- **打包方式**：`python tools/pack.py store`——按显式文件清单生成并自校验（清单外文件、敏感词一律拒绝）；**不要整目录压缩**。
- 包内容（2026-10-17 重新打包，pack.py 内置校验通过：29 个条目与清单逐条一致、无敏感词）：
  - `manifest.json`；
  - `src/`：`dictionary.json`、`content.js`、`background.js`、`options.html/css/js`、`popup.html/css/js`、`manual.html`（使用指南）、`manual-images/`（7 张界面截图）；
  - `icons/`：`icon16/48/128.png` + `logo300.png` + `promo440x280.png`；
  - 文档六件：`README.md`、`PRIVACY.md`、`LICENSE`、`CHANGELOG.md`、`CONTRIBUTING.md`、`NOTICE.md`；
  - **不含**任何测试页、样例文档与内部记录。

### 2.3 表单字段

| 字段 | 我们的填法 | 备注 |
|------|-----------|------|
| Extension name | `站点链接助手` | 取自 manifest `name`，**Partner Center 里只读**，改名要重新传包 |
| Short description | 取自 manifest `description`（已写好） | 同上，只读 |
| Description | 250–10000 字符，每种语言必填 | 建议直接放 README 的功能段（中英双语各一份） |
| Category | 选 `Productivity`（效率工具） | 必填 |
| Search terms | 建议填：`站点链接` `学术` `知网` `链接` `科研工具` | 可选，最多 7 个、每个 ≤30 字符 |
| Privacy policy URL | GitHub 仓库的 PRIVACY.md 链接（建仓后填） | 见 §5 |
| Website / Support | GitHub 仓库 / Issues | 可选 |
| 年龄分级 | Everyone / 3+ | 官方文档未展开，第三方提交案例提到 Edge 要求填 |

### 2.4 Privacy 页（数据使用声明）

- Single Purpose：一段话说清插件只做一件事——把站点名称转成链接。
- Permission justification：`storage` = 保存用户的分类开关与"站点修正"设置（改网址 / 触发词 / 自定义站点）。
- 数据使用披露：**全部选"不收集"**（我们确实不收集）。
- 远程代码：无（全部本地资源）。

## 3. 审核

- 官方口径："The certification process can take **up to seven business days** after you submit the extension."
- 第三方实际提交案例口径：通常 3–4 天（非官方，仅供参考）。
- **每次更新都要升 manifest 里的 `version`，重新打包重新审。**
- 更新已有扩展时，认证备注一句话即可，如「适配更多网站；修复部分页面不生效的问题」——不列站点、不写来源。
- 用远程代码会明显拉长审核——我们没有。

## 5. 提交流程

1. Partner Center 新建扩展 → 上传 zip。
2. 填 Availability（Visibility: Public；Markets 全选）。
3. 填 Properties（Category 等）。
4. 填 Privacy（§2.4）。
5. 填 Store listings（名称/描述/logo/截图/搜索词）。
6. **Notes for certification**（给审核测试员的说明，建议认真写，能防"不知道怎么测"被打回）。可直接用：

   > 您好！本扩展会把网页正文中的站点名称（如"中国知网""国家统计局""arXiv"）自动转成可点击链接。
   > 测试步骤：① 打开任意含站点名称的网页（或扩展包同目录的 demo.html），正文中的站点名会变成链接，代码块和已有链接不受影响；② 点击工具栏上的扩展图标会弹出速控面板：在输入框里输入站点名（如 steam、淘宝）可直接打开官网；也可勾选 / 取消 6 个站点分类（默认全开），已打开的页面即时生效；③ 点"扩展选项"进入设置页：上半部分是分类开关与"点击链接时"两个并列开关——"自动复制句中的关键词，并在新页面自动粘贴"（点击网页里生成的链接，会自动复制该句《书名号》/引号/冒号后的内容，同句有多个会全部复制；官网在新窗口打开后，在那个窗口里点输入框即自动粘贴，可粘多次）与"在新窗口打开链接（而不是新标签页）"（点击链接默认新开一个浏览器窗口，位置随当前窗口自动避让：靠左放右、靠右放左；两者默认开启、可分别关闭，中键 / Ctrl+点击仍按浏览器默认开新标签页）；中部"我添加的站点"收纳用户自添加站点（与词库分开存放），下半部分"站点修正"可以修改某条目的网址、补充触发词、停用条目（改动仅存在于本地）；④ 首次安装时会自动打开一页《使用指南》（给用户的上手说明，可随时关闭）。
   > 扩展无网络请求、不收集任何数据。感谢审核！

7. 提交，等结果（邮箱通知）。
